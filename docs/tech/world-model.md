# 世界の作り方

コードは `src/world/`（計算）と `src/render/`（描画）。ここには、コードを読むだけでは分からない決まりと理由を書く。

## 単位と座標系

| 項目 | 決まり |
|------|--------|
| 座標系 | **J2000 の赤道座標系（EQJ）**。+X が春分点の方向、+Z が天の北極。astronomy-engine と HYG が同じ座標系なので、変換せずに重ねられる |
| 太陽系の単位 | km。原点は太陽の中心 |
| 恒星の単位 | パーセク（pc）。原点は太陽 |
| 時刻 | 端末の時計の UTC（`src/world/clock.ts`）。全員でそろえる補正は、他のプレイヤーの機能を作るときに足す |
| 天文単位・パーセク・光年 | `src/world/units.ts`。天文単位は IAU 2012 の定義値 149,597,870.7 km、パーセクは 648000/π 天文単位、光年はユリウス年 × 光速 |

## 天体の一覧と id

`src/world/solar-system.ts`。天体は**一覧（registry）に登録して使う**。描画・衝突・基準の天体・レーダーは、どれもこの一覧を見る。

- 最初から入っているのは `CORE_BODIES`（太陽・惑星・冥王星・月・ガリレオ衛星）。系外惑星は、いる恒星系が変わるたびに入れ替える（`registerBodies`・`unregisterBodies`。[`exoplanets.md`](exoplanets.md)）
- 一覧に無い天体（遠くの恒星系の惑星に置かれたワープホールなど）は、`setBodyResolver` で渡した関数で調べる
- 位置の決め方（`motion`）：astronomy-engine の `HelioVector`（太陽・惑星・冥王星・月）、`JupiterMoons`（ガリレオ衛星）、ケプラーの軌道（`src/world/kepler.ts`。系外惑星など）、動かない（系外の恒星）
- 同じ時刻の位置は覚えておき、1 フレームに何度聞かれても計算は 1 回

### 天体の id

id は**住所の番号を含む形**にした。サーバーが天体の一覧を持たなくても、id だけで住所の番号を決めて、正しいかを確かめられるようにするため（`src/world/address.ts` の `bodyAddress`）。

| 天体 | id | 例 |
|------|----|----|
| 太陽・惑星・冥王星・月 | 英語の名前（これまでどおり） | `Earth`、`Moon` |
| 太陽系の衛星 | `S` ＋惑星の番号 ＋ `.` ＋衛星の正式な番号 | イオ（木星 I）＝`S5.1`、タイタン（土星 VI）＝`S6.6` |
| 小惑星・準惑星 | `A` ＋小惑星番号 | ケレス＝`A1` |
| 系外惑星 | 恒星系の記号 ＋ `.` ＋恒星に近い順の番号（自動で作った惑星で、作り方の世代が 2 以上なら `~世代`） | `H70666.2`、`G…T.1~2` |
| 系外惑星の衛星 | 惑星の id ＋ `.` ＋惑星に近い順の番号（要件 F26） | `H50229.3.1` |
| 人工衛星 | `N` ＋カタログ番号（NORAD）。住所は地球のまわり（惑星 3・衛星 0。[`satellites.md`](satellites.md)） | ISS＝`N25544` |

- 衛星（ガリレオ衛星以外）と大きな小惑星は、起動のときにデータから一覧に足す（[`small-bodies.md`](small-bodies.md)）
- レーダーには、天体が多いので、半径 200 km 以上か 1,000 万 km より近い天体だけを出す

## 天体の見た目

- 画像は `src/render/body-looks.ts` の `TEXTURE_FILES` のファイル名（Solar System Scope の配布名のまま）で `public/textures/` に置けば使われる。地球と月は必ずある。ほかは無ければ模様を自動で描く（要件 F19）
- 自動の模様は `src/world/surface.ts`。球の上の 3 次元のノイズで描くので、経度 0 度のつなぎ目が出ない。整数の乱数（`src/world/random.ts`）だけで作るので、同じ種なら誰の端末でも同じ模様。縞の星（ガス・氷の惑星）は緯度に沿った 1 次元のノイズで縞の幅と濃さを不ぞろいにし、岩の星はノイズで色を混ぜてくぼみを暗くする
- 模様の色は**見た目のための値**（観測の値ではない）。天体ごとの色は `SURFACE_LOOKS`
- 2026-11-05：最初は縞を sin の波で描いたが、木星が同じ幅の縞の並びに見えたので、1 次元のノイズに変えた。縞を乱す強さも 0.35 では渦に見えたので 0.1 にした
- **模様は Web Worker で描く**（`src/render/surface-worker.ts`・`surface-painter.ts`）。描けるまでは灰色 1 ピクセルの仮の画像を貼り、できたら差し替える。2026-11-05 に Node で測ると、1 枚 512×256 で約 180 ms、256×128 で約 44 ms、128×64 で約 11 ms（ノイズの格子の値を求める関数を書き下して、約 350 ms から半分にした）。描画のループと同じスレッドで描くと、恒星系に入るたびに画面が止まる
- 画像の大きさ：太陽系の半径 1,000 km より大きい天体は 512×256、それ以外と系外惑星は 256×128、半径 300 km 以下は 128×64
- **土星の環**：内側と外側の半径は NASA の Saturnian Rings Fact Sheet の D 環〜A 環（66,900〜136,775 km）。帯ごとの濃さは見た目のための値で、観測の光学的厚さの大小の並び（B 環が最も濃く、カッシーニの間隙が薄い）に合わせた。環の画像も自動で描く（`paintRing`）。環は土星の赤道の面（自転の向き `bodyFixedToEqj` に付ける）

### 大気・恒星・環の影（要件 F25）

`src/render/body-effects.ts`。どれも見た目のための近似で、光の散乱や影を本物どおりには計算していない。

- **大気**：天体より少し大きい殻を重ね、ふちだけ光らせて足し合わせる（加算合成）。昼の側だけ明るく、昼夜の境目の少し向こうまで薄く残す。色・厚さ・明るさは `src/world/solar-system.ts` の `SOL_ATMOSPHERES`（地球・金星・火星・木星・土星・天王星・海王星）。厚さは半径の 1.2〜3%（本物の大気の高さより厚い。本物どおりだと画面で 1 ピクセルにもならないため）。系外惑星の決まりは [`exoplanets.md`](exoplanets.md)
- **恒星**：表面は周辺減光（I(μ)/I(1) = 0.4 + 0.6μ。太陽の可視光のおおよその値）と、ゆっくり動く粒の模様（粒状斑）と大きなまだら（黒点）。まわりに、半径の 6 倍の大きさの光の広がり（カメラの方を向く板）。2026-11-05：最初の 12 倍・強めの光では、太陽から 0.02 AU で画面全体が白く覆われたので弱めた
- **環の影**：本体の表面の点から恒星へ向かう線が環の面に当たれば、そこの環の濃さの分だけ暗くする。環の上の点から恒星へ向かう線が本体を通れば、環を暗くする
- **環の明るさ**：ふつうの照明では、光が環の面にほぼ真横から当たると真っ暗になる（2026 年の土星は春分の直後なので、そうなる）。環が見えなくなるので、光の当たる角度の平方根で弱め、最低でも 0.25 は残すようにした（現実の春分の頃の環は、もっと暗い）

## 天体の位置と向き

- 位置は astronomy-engine の `HelioVector`（太陽中心・光の届く時間の補正なし）
- 向きは `RotationAxis` の北極の向き（α0・δ0）と本初子午線の角度（W）から、IAU の定義どおり `Rz(α0+90°)·Rx(90°−δ0)·Rz(W)` で作る（`bodyFixedToEqj`）
- three.js の球は、画像の中央（経度 0 度）が +X・北極が +Y・東経 90 度が −Z。天体に固定した座標（x：本初子午線・y：東経 90 度・z：北極）とのつなぎは `src/render/orientation.ts`
- **潮汐ロック**（ガリレオ衛星など）：本初子午線（x 軸）をいつも親の天体に向け、z 軸を公転の面の北にする。月と同じく親に同じ面を向ける。ガリレオ衛星の公転の面は、`JupiterMoons` の位置と速さの外積で出す
- **確かめ方**：太陽が真上にくる地点の緯度・経度が現実と合うかをテストしている（`src/world/solar-system.test.ts`。UTC 正午に経度 0 度付近、夏至に北緯 23.4 度）。自転の向きをわざと逆にするとテストが落ちることも確かめた

## 自分の位置の持ち方（基準の天体）

自分の位置は「基準の天体の中心からの相対位置」で持つ（`src/world/observer.ts`）。

- **理由**：地球は太陽のまわりを秒速約 30 km で回る。太陽中心の位置で持つと、止まっているつもりでも地球がどんどん離れていく。基準の天体と一緒に動くことで、地球のそばに「止まって」いられる
- **基準の選び方**：いる場所を影響圏に含む天体のうち、影響圏がいちばん小さい天体。どこにも入っていなければ太陽。毎フレーム選び直し、選び直しても位置は変えない
- **影響圏の値**：Laplace の影響圏 r = a·(m/M)^(2/5)（a は回っている軌道の半径、m/M は質量の比）。地球は約 92.5 万 km、月は約 6.6 万 km、木星は約 4,820 万 km。式で計算し直して一致を確かめた。天体ごとに `anchorRadiusKm` に持つ
- **質量の分からない衛星**（いまはガリレオ衛星）は、**半径の 10 倍**を基準にする範囲にした（決まりとして置いた値）。ガリレオ衛星の Laplace の影響圏は半径の約 4〜16 倍。衛星は親の惑星のまわりを速く回る（イオは秒速約 17 km）ので、基準にしないと、そばに止まっていられない
- 現実の宇宙船の動き（重力に引かれる）とは違う。操縦しやすさを優先した決まり

## 天体に近づける距離

要件 F11。`src/world/collision.ts`。

- 表面からの最低の高さは **100 km か、半径の 1% の大きい方**。地球・月・火星などは 100 km、木星は約 700 km、太陽は約 7,000 km
- **ただし半径の半分より高くはしない**（2026-11-05 から）。小さな天体（小惑星・小さな衛星・人工衛星）にも近づけるように。半径 14 km のエロスなら 7 km、半径 1 km なら 0.5 km、ISS（半径 55 m）なら 27 m
- 100 km は、地球で「宇宙の境目」とされる高さ（カーマン・ライン）。ISS（高さ約 400 km）を後で置いたときに、そばまで行ける高さにした
- 近づきすぎたら、天体の中心から外へ押し戻す。基準の天体だけでなく、すべての天体に効く
- 2026-11-05：秒速 7,276 km で地球に突っ込んで、表面から 100 km で止まることを画面で確かめた

## ワープホール

要件 F9。`src/world/warp.ts`（位置の計算）、`src/world/warp-schema.ts`（形の確かめ。サーバーと共有）、`src/net/warp-repository.ts`（サーバーとのやりとり）、`src/render/warp-view.ts`（描画）。サーバー側は [`server.md`](server.md)。

- **置く場所**：自分の **2,000 km 前方**に、自分の方を向けて置く。最初は自分のいる場所そのものに置いていたが、自分が輪の中心に入り、輪が画面を横切る太い帯に見えたのでやめた（2026-11-05）。前方が天体にふさがれているときは、天体に近づける距離の外まで押し戻す
- **位置の持ち方**：自分の位置と同じく、置いたときの基準の天体からの相対位置。地球の近くのワープホールは、地球と一緒に動く
- **ワープした先**：輪の正面 2,000 km（置いた人が立っていた位置）に出て、輪の方を向く
- **名前**：宇宙の住所のコード（下の「宇宙の住所」）。番号はサーバーが振る。自由な名前は付けない
- **保存**：サーバー（D1）に保存し、全員で共有する（2026-11-05 から。それまではブラウザの中だけの仮の保存だった）
- **1 人 3 個まで、消せるのは置いた本人だけ**（要件 F13）

## 宇宙の住所

要件 F12。`src/world/address.ts`。住所（日本 › 東京都 › 大田区 › …）のように、大きな範囲から順に狭めて 1 か所を指す。

```
MW-ORI-SOL-3-1-002
銀河-銀河の腕-恒星系-惑星-衛星-番号
読み：天の川銀河 オリオン腕 太陽系 地球 月 2番
```

| 階層 | 決め方 | 例 |
|------|--------|----|
| 銀河 | いまは天の川銀河だけ | `MW` |
| 銀河の腕 | **恒星系のある腕**。銀河のモデルで決める（[`galaxy.md`](galaxy.md) の「住所との関係」）。`SGR` いて・りゅうこつ腕、`PER` ペルセウス腕、`NOR` じょうぎ・外縁腕、`SCU` たて・ケンタウルス腕、`ORI` オリオン腕、`BLG` 中心部、`HAL` ハロー。太陽系はオリオン腕 | `ORI` |
| 恒星系 | 置く場所に**いちばん近い恒星**（太陽・本物の星・自動で作った星）。太陽系は `SOL`、HYG の星は `H` ＋ HYG の id、自動で作った星は `G` ＋ マス目と番号 | `SOL`、`H32263`（シリウス）、`GHU8I00I007T` |
| 惑星 | 基準の天体の id で決める（上の「天体の id」）。太陽系の惑星は太陽に近い順（水星 1 〜 海王星 8、冥王星 9）。小惑星・準惑星は `A`＋小惑星番号（要件 F21）。系外惑星は恒星に近い順（要件 F23）。惑星の近くでなければ 0 | `3`（地球）、`A1`（ケレス） |
| 衛星 | その惑星の衛星の正式な番号（要件 F20。読みはローマ数字）。衛星の近くでなければ 0 | `1`（月）、`6`（タイタン） |
| 番号 | その住所（番号の前まで）での通し番号。3 桁まで 0 で埋める（1000 以上はそのまま）。消しても使い回さない | `002` |

- 基準の天体が、その恒星系の天体でなければ（恒星系の間の宇宙など）、惑星・衛星は `0-0`
- 恒星系の記号には、系外惑星のデータにだけある恒星（HYG に無い恒星）の `E`＋36 進 7 桁、パルサーの `P`＋J 名、白色矮星の `W`・ブラックホールの `B`＋36 進 7 桁もある（[`compact-objects.md`](compact-objects.md)）
- 階層の数は 6 で固定。区切りの `-` で分ければ、どの階層かが必ず分かる
- 星の id のために、星のデータ（`stars.bin`）に HYG の id を足した（下の「恒星のデータ形式」）

## レーダー

要件 F10。`src/world/radar.ts`（計算）、`src/ui/Radar.tsx`（表示）。

- 円の上が自分の進む方向（カメラの −Z）。自分の水平面に落とした向きで置く
- 中心からの距離は、**実際の距離の対数**。中心が 1,000 km、ふちが 100 億 km（海王星の外まで）。それより遠い物はふちに薄く置く
- 上下は円に描けないので、自分より上は塗りつぶし（●）、下は輪郭だけ（○）
- 天体の名前は、近い 3 つだけを小さく出す。宇宙の中の天体には名前を出さない（[`../design/README.md`](../design/README.md)）
- ワープホールの名前は、住所の恒星系から後ろだけ（例：`SOL-3-0-001`）。レーダーが狭いため
- 他のプレイヤーの宇宙船（`kind: 'ship'`）も映せる形にしてある。他のプレイヤーの機能ができたら足す
- ワープホールが同じ方向に集まると、名前が重なって読めない（いまの制限）

## 恒星のデータ形式

`public/data/stars.bin`。`npm run stars`（`tools/build-stars.mjs`）が HYG v4.4 から作る。

- little-endian の 32bit 小数を、1 個の星につき 6 個並べる：x・y・z（pc・EQJ）、**絶対等級**、色指数 B−V（無ければ NaN）、HYG の id（宇宙の住所に使う）
- 太陽は除く（太陽系の側で描く）。**距離の分からない星（約 1 万個）も除く**（3 次元の場所に置けないため。以前は 10 万 pc 先に仮に置いていたが、銀河の外から見ると太陽を囲む殻に見えるため 2026-11-05 にやめた）。本来の明るさの順に並べる
- 109,389 個・2.50MB

## 星の明るさ

- 星ごとに絶対等級を持ち、**カメラからの距離で見かけの等級を GPU で毎フレーム計算する**（`src/render/star-sprites.ts`）。m = M + 5·log10(d / 10 pc)。本物の星にも自動で作った星にも使う
- 見かけの等級から大きさ・明るさを決める数は `STAR_LOOK`（`src/world/stars.ts`）。CPU の `starAppearance`（テスト）とシェーダーが同じ数を使う
- **14 等より暗い星は消える**（10 等から少しずつ）。銀河の外から見たとき、太陽のまわりの本物の星が最小の明るさで重なって、明るい玉に見えたため（2026-11-05）
- 同じ場所に `stars.LICENSE.txt` を置く（CC BY-SA 4.0 の継承。[`credits.md`](credits.md)）

## 描画の分け方

- **2 つの場面に分けて描く**：恒星（pc 単位・星専用のカメラ）を先に描き、奥行きを消してから太陽系（km 単位）を描く。単位の違う世界を 1 つの場面に入れないため
- **自分を原点に置く**：天体の位置から自分の位置を引く計算は倍精度（JavaScript）で済ませ、結果だけを GPU（32bit）に渡す
- **奥行き**：対数の奥行き（`logarithmicDepthBuffer`）。逆向きの奥行きは WebGL2 の古い端末で使えないことがあるため選ばなかった
- **星の描き方**：WebGPU は点を 1 ピクセルでしか描けないので、小さな板（Sprite）を星の数だけまとめて描く（`src/render/starfield.ts`）
- **画面の表示（HUD）**：世界のループが 1 秒に 4 回だけ値を書き、React が読む（`src/ui/hud-store.ts`）

## いまの制限（仮のもの）

- **惑星は遠いと小さすぎて見えない**。地球と月以外は、画面で 1 ピクセルより小さくなる。場所はレーダーで分かる。宇宙の中には大きな名前を出さない（デザインの決まり）
- **地表の近くでは地球の画像がぼやける**。画像が 2K（2048×1024）のため。高さ 100 km まで近づけるので、近いときだけ細かい画像を読む仕組みが要る
- **星の見た目**（大きさ・明るさの付け方）は仮。`src/world/stars.ts` の `starAppearance`
- **操縦は仮**（`src/controls/flight.ts`）
- **置く場所はブラウザが送ったものを信じている**（[`server.md`](server.md) の「信用していること」）
