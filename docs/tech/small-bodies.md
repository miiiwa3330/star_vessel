# 太陽系の衛星と小惑星

コードは `src/world/small-bodies.ts`（データから天体の一覧を作る）、`src/render/asteroid-field.ts`（小惑星の光の点）、`tools/build-moons.mjs`・`tools/build-asteroids.mjs`（データの変換）。

## 衛星（要件 F20）

| 項目 | 内容 |
|------|------|
| 対象 | JPL の衛星の表にある、**正式な番号を持つ衛星**（3 桁の id：惑星の番号 × 100 ＋ 衛星の番号）。188 個（火星 2・木星 72・土星 66・天王星 28・海王星 14・冥王星 5、月 1）。番号の無い仮符号の衛星（273 個）は、住所の番号（要件 F20：正式な番号）が付けられないので外した |
| 軌道 | JPL Horizons の**接触軌道要素**（惑星の中心から、ICRF の赤道を基準にした面。元期 2026-11-01）。周期だけは JPL Planetary Satellite Mean Elements の値（長い期間の平均の速さ） |
| 大きさ | ① JPL Planetary Satellite Physical Parameters の平均半径（46 個）、② Horizons の半径（20 個）、③ Horizons の絶対等級 V(1,0) から反射率 0.04 を仮定して推定（26 個）、④ どれも無いものは**仮に半径 1.5 km**（96 個。見つかったばかりの数 km 以下の不規則衛星） |
| 基準の天体にする範囲 | GM が分かる衛星は Laplace の影響圏 a·(m/M)^(2/5)（惑星の GM は astronomy-engine）。分からない衛星は半径の 10 倍 |
| id・住所 | `S`＋惑星の番号＋`.`＋衛星の番号（例：タイタン＝`S6.6`）。主な衛星は日本語の名前（タイタン・エンケラドゥスなど） |
| 取り直し | `npm run moons`（`tools/.cache/moons/` に置く。コミットしない） |

- **月とガリレオ衛星はデータから作らない**。astronomy-engine の方が正確なため（`CORE_BODIES`）
- 取れる最後の日が元期より前の衛星（探査機の観測だけで軌道が決まった小さな衛星。例：ダフニス）は、取れる最後の日（2018-01-16）の要素を使う
- 向きは潮汐ロック（惑星に同じ面を向ける）。タイタンには大気の光の輪を付けた

### 平均軌道要素をやめた理由

最初は JPL の平均軌道要素の表（Laplace 面・赤道面・黄道面を基準にした角度と、近点・交点の歳差の周期）から位置を出した。火星・木星・冥王星の衛星は Horizons と 0.1 度で合ったが、**土星と天王星の衛星は最大 170 度ずれた**。元期を一律にずらしても合わず（平均で 7〜15 度残る）、こちらでは表の角度の基準を正しく読み解けなかった。そこで、全部の衛星を Horizons の接触軌道要素にそろえた。

### 位置の精度（2026-11-05 に Horizons で確かめた）

元期（2026-11-01）から 4 日後の位置を、Horizons の位置と比べた（`src/world/small-bodies.test.ts`）。

| 衛星 | ずれ（軌道の半径に対する割合） |
|------|------|
| タイタン | 1% 未満 |
| トリトン | 1% 未満 |
| フォボス（4 日で約 12 周） | 約 5% |

- 接触軌道要素は、その時刻の軌道。惑星の扁平さなどで軌道はゆっくり変わるので、**元期から離れるほどずれる**（速く回る衛星ほど早くずれる）。年に一度くらい `npm run moons` で作り直す

## 小惑星・準惑星（要件 F21）

| 項目 | 内容 |
|------|------|
| 出どころ | JPL Small-Body Database Query API。**番号の付いた小惑星すべて**（太陽系外縁天体を含む）。2026-11-05 に 895,909 個 |
| 軌道 | 太陽を中心にした接触軌道要素（J2000 の黄道座標。黄道傾斜角は JPL と同じ IAU 1976 の 84381.448″）。元期は天体ごと（多くは 2026 年） |
| 取り直し | `npm run asteroids`（`tools/.cache/asteroids/` に置く） |

### 光の点として描く（すべて）

- `public/data/asteroids-0.bin`〜`-3.bin`。1 個につき 9 個の 32bit 小数（番号・絶対等級 H・a・e・i・Ω・ω・M・元期）。明るい順に並べ、0 番は **H < 15 の 75,854 個**（2.7 MB）、残りを 10 MB 以下ずつ（Cloudflare の静的なファイルの上限 25 MiB に収めるため）
- **PC はすべて、スマホ（指で操作する端末）は 0 番だけ**を、起動してから裏で読み込む（要件 F21 の 2026-11-05 の決定）。PC でも URL に `?asteroids=bright` を付けると 0 番だけになる（重さの確かめ用）
- 位置は**頂点シェーダーでケプラーの方程式を解く**（ニュートン法 6 回）。90 万個を CPU で毎フレーム計算するのは重すぎるため。GPU の 32bit の計算なので位置の誤差は数千 km あるが、光の点としては見分けられない
- 明るさは見かけの等級 m = H + 5·log10(r·Δ)（位相による暗さは無視）。暗くても最低の明るさを残すので、離れると小惑星帯が輪として見える。太陽から 2,000 AU より遠いときは描かない

### 近くの小さな小惑星（2026-11-05 から）

- 2 秒ごとに、自分から 200 万 km 以内の近い順 8 個の小惑星を探し、球の天体として一覧に入れる（`src/world/asteroid-search.ts`）。住所（`A`＋番号）が付き、基準の天体・近づける距離にもなる
- 90 万個すべてを毎回計算すると重いので、先に「太陽からの距離が近日点〜遠日点の範囲に入るか」で絞り、残ったものだけケプラーの方程式を解く
- 大きさは絶対等級 H から反射率 0.15（小惑星のおおよその平均）を仮定して推定する（D = 1329 km / √p × 10^(−H/5)）。形は球（本物の多くはいびつ。例：エロスは細長い）
- 光の点は、自分から 20 万 km 以内では消す（32bit の計算でずれた点が、倍精度で描く球の横に見えないように）
- 遠くの小さな小惑星に置かれたワープホールの位置は、番号でデータから探して出す
- 2026-11-05：エロス（433 番、推定の半径 14 km）の表面から 26 km まで近づき、球として見えることを確かめた。ケレスは、光の点のデータ（32bit）からの位置でも Horizons と 0.1% 以内で合う（テスト）

### 球として描く（大きな天体）

- **直径 200 km 以上（SBDB の値）、または直径が分からず H ≤ 3** の 39 個（`asteroids-large.json`）。住所が付き（`A`＋小惑星番号）、近づける距離・基準の天体にもなる
- 冥王星（134340）は太陽系の主な天体として別に持つので外す。IAU の準惑星（ケレス・エリス・ハウメア・マケマケ）は種類を準惑星にする
- 位置は倍精度のケプラーの軌道。ケレスとエリスは Horizons と太陽からの距離の 0.1% 以内で合う（テスト）
- **直径が SBDB に無い大きな太陽系外縁天体**：

| 天体 | 直径 | 決め方 |
|------|------|--------|
| エリス | 2,326 km | 観測値（Sicardy ほか 2011、恒星の掩蔽。Wikipedia の出典付きの値で確かめた） |
| マケマケ | 1,430 km | 観測値（Brown 2013） |
| ハウメア・セドナ・クワオアー・オルクス・ゴンゴン | 2,275 ／ 1,216 ／ 800 ／ 910 ／ 1,049 km | **推定**：D = 1329 km / √p × 10^(−H/5)、反射率 p = 0.3 と仮定。観測値（ハウメア約 1,600、クワオアー約 1,100 km など）と最大で 4 割ほど違う |

- 自転の軸と周期（5〜25 時間）は番号を種にして決める（見た目のための値）

## いまの制限

- 番号の無い仮符号の衛星・小惑星は入れていない
- 衛星・小惑星の模様は自動で描いた岩・氷の模様（画像は無い）
