# 太陽系の外の惑星

コードは `src/world/planets.ts`（恒星系の天体を作る）、`src/world/star-systems.ts`（恒星系の記号から恒星を引く・いる恒星系の天体を登録する）、`src/world/exoplanet-data.ts`（データの読み方）、`tools/build-exoplanets.mjs`（データの変換）。

## 全体の流れ

1. 毎 2 秒、いちばん近い恒星（太陽・HYG の星・系外惑星のデータの星・自動で作った星）を調べる（`nearestSystem`）
2. 恒星系が変わったら、前の恒星系の天体を一覧から外し、新しい恒星系の恒星と惑星を登録する（`StarSystems.enter`）。描画・衝突・基準の天体・レーダーは、一覧にある天体をそのまま使う
3. 実在の系外惑星のデータがある恒星はその惑星、無い恒星は種から作った惑星（要件 F22）
4. 遠くの恒星系の惑星（そこに置かれたワープホールの位置など）は、天体の id から恒星系を引いて作る（`setBodyResolver`）。64 個まで覚えておく

## 実在の系外惑星のデータ

| 項目 | 内容 |
|------|------|
| 出どころ | [Open Exoplanet Catalogue](https://github.com/OpenExoplanetCatalogue/open_exoplanet_catalogue)（Hanno Rein ほか）。MIT ライセンス。`systems/` の XML |
| 取得 | `npm run exoplanets`（`tools/.cache/` に git で取得。コミットしない）。2026-11-05 に commit `30e582f` から作った |
| 使う惑星 | `<list>Confirmed planets</list>` の惑星だけ（候補・撤回された惑星は使わない）。距離の分からない系、軌道長半径と周期の両方が分からない惑星は外す |
| 結果 | 恒星系 3,704（星のデータの星と一致 769・新しい恒星 2,935）、惑星 4,972。外したもの：確定していない 117、距離が無い 211、軌道が無い 105 |
| 形式 | `public/data/exoplanets.json`（約 0.9 MB）。恒星系ごとに記号・名前・恒星（質量・半径・温度）と、恒星に近い順の惑星 `[名前, 軌道長半径 AU, 周期 日, 離心率, 傾斜角, 昇交点, 近点引数, トランジットの時刻 JD, 半径 RJ, 質量 MJ, 温度 K]`（分からない値は null） |
| ライセンスの表示 | `public/data/exoplanets.LICENSE.txt`（MIT の条件の、著作権の表示と許諾の文。ツールが配布元の README からそのまま写す） |

- 軌道長半径と周期の片方しか無い惑星は、ケプラーの第 3 法則で補う（恒星の質量が分からなければ太陽と同じとする）
- 2026-11-05 時点のデータ。新しい惑星が見つかったら `npm run exoplanets` で作り直す。作り直すと、惑星の番号（恒星に近い順）がずれることがある（要件 F23 で了承済み）

### 恒星の見つけ方

- XML の赤経・赤緯・距離から方向と距離を出し、星のデータ（`stars.bin`）の星のうち、**方向のずれが 0.03 度以内・距離の比が 0.6〜1.6 倍**の星で、方向がいちばん近いものを同じ恒星とする。その恒星系は `H`＋HYG の id
- 見つからない恒星（暗くて HYG に無い星。TRAPPIST-1 など）は、新しい恒星として足す。記号は `E`＋系の名前の FNV-1a ハッシュ（36 進 7 桁）。星空にも描く（`createExtraStarfield`）。絶対等級は V 等級と距離から（V 等級が無ければ半径と温度から）、色は温度から（Ballesteros 2012 の式を逆に解く）
- 星のデータの星に名前（HIP 番号など）が無いので、名前では探さない

## 自動で作る惑星（世代 1）

`generatedPlanetsV1`。恒星系の記号を種にするので、同じ恒星には誰の端末でも同じ惑星ができる。**数（惑星があるか・いくつか・木星型か）は乱数との大小の比べだけで決める**（端末による計算の差で数が変わらないように。AGENTS.md）。

### 恒星の性質

| 項目 | 決め方 | 出典 |
|------|--------|------|
| 温度 | 色指数 B−V から | Ballesteros（2012） |
| 質量 | 絶対等級から、主系列の表の間を直線でつなぐ | Pecaut & Mamajek（2013）の主系列の表から主なスペクトル型の値を拾った、おおよその値 |
| 半径 | R = √L / (T/T☉)²（放射補正は無視） | — |
| 赤色巨星 | B−V ≥ 0.9 かつ絶対等級 < 2 のとき。質量は 1.2 とする | 決まりとして置いた値 |

### 惑星の数と種類

**観測の割合に合わせた近似**（要件 F22）。どれも、観測の論文の結果を丸めて単純にした値で、正確な再現ではない。

| 恒星の種類 | 惑星を持つ割合 | 木星型を持つ割合（周期 200 日より外側の惑星ごと） | 根拠 |
|------------|----------------|---------------------------------------------------|------|
| M 型（0.6 太陽質量未満） | 0.85 | 0.03 | M 型星は周期 200 日以内に平均約 2.5 個の惑星を持つ（Dressing & Charbonneau 2015）。木星型は少ない |
| FGK 型（0.6〜1.4） | 0.75 | 0.10 | 平均して 1 つ以上の惑星（Cassan ほか 2012）。木星型は約 10%（Cumming ほか 2008） |
| A・B 型（1.4 以上） | 0.35 | 0.20 | 重い星ほど木星型が多い（Johnson ほか 2010）。小さな惑星は見つかりにくく分かっていない |
| 赤色巨星 | 0.15 | 0.10 | 巨星のまわりの惑星は少ない（Reffert ほか 2015） |

- 惑星の数（持つ場合）：1〜8 個を 0.30・0.22・0.17・0.12・0.09・0.06・0.03・0.01 の割合で（Kepler の多惑星系の数の並びを丸めた）
- いちばん内側の周期：1.5〜40 日（対数で一様）。外側へは周期の比 1.4〜3.0 で並べる（Kepler の多惑星系の周期の比は 1.5〜2 付近が多い。Fabrycky ほか 2014）
- 大きさ：周期 100 日より内側は、55% が 0.8〜1.7 地球半径（スーパーアース）、残りが 1.8〜3.5（サブネプチューン。半径の谷 Fulton ほか 2017 の両側）。外側は 60% が 1〜2、残りが 2〜6。木星型は 0.8〜1.3 木星半径。いちばん内側が周期 10 日より短ければ、1% でホットジュピター（Wright ほか 2012 の約 1%）
- 質量：半径から Chen & Kipping（2017）の関係で出す（木星型は 0.3〜3 木星質量）
- 離心率：小さな惑星は 0〜0.08、木星型は 0〜0.3
- 並ぶ面：系ごとに向きはでたらめ（cos i を一様に）で、惑星どうしは ±2 度だけずらす
- 恒星の半径の 3 倍より内側になる惑星は作らない（赤色巨星など）
- **衛星は作らない**（いまの決まり）

### 世代（要件 F24）

- いまの作り方は世代 1（`PLANET_GENERATION`）。世代 1 の惑星の id は `G…T.2` のように世代を書かない
- 作り方を変えるときは、`generatedPlanetsV1` を残したまま新しい世代の関数を足し、`PLANET_GENERATION` を上げる。新しい世代の惑星の id は `G…T.2~2`。前の世代の id を基準にしたワープホールは、前の世代の作り方で位置を出し続ける

## 軌道と向き

- 公転は**ケプラーの軌道で、現実の時刻に合わせて動かす**（要件 F23。`src/world/kepler.ts`）
- **実在の惑星**の軌道の向きは、空の面を基準にする（`skyFrame`）：z が恒星から太陽（地球）への向き、x が空の北、y = z × x。データの傾斜角は、空の面に対する値（90 度で真横から見る）
- 分からない向き（傾斜角・昇交点・近点引数）と、軌道の上のどこにいるかは、惑星ごとの種から決める（傾斜角は cos i を一様に）
- **トランジットの時刻が分かる惑星**は、その時刻に恒星の手前（真近点角 90°−ω）にいるように合わせる。つまり、地球から見てトランジットする惑星は、ゲームの中でも同じ時刻に恒星の前を横切る（テストで確かめている）
- 周期 10 日より短い惑星は恒星に同じ面を向ける（潮汐ロック）。ほかは 8〜40 時間で自転
- **基準の天体にする範囲**：Laplace の影響圏 a·(m/M)^(2/5)。ただし半径の 3 倍より小さければ半径の 3 倍
- **恒星**は動かない（`fixed`）。恒星のまわりで惑星から離れているときは、太陽を基準にした位置で持つ（恒星が動かないので、そのままで止まっていられる）。画面の高さは、いる恒星系の恒星の表面から出す

## 見た目

- `planetLook`：半径で種類を分け（1.6 地球半径まで岩、6 まで氷＝海王星型、それより大きいとガス＝木星型）、温度（データ、無ければ平衡温度 T★√(R★/2a)）で色を決める。色の組は種から選ぶ。**見た目のための決まり**で、観測の値ではない
- 模様は太陽系と同じく自動で描く（`src/world/surface.ts`）。恒星系に入るたびに作るので、画像は 256×128 と小さくしている
- 恒星は温度からの色で光る球。光の色も恒星の色にする

## 確かめたこと（2026-11-05）

- テスト：同じ恒星から同じ惑星、番号が恒星に近い順で id から住所の番号が決まる、太陽に似た恒星の約 4 分の 3 が惑星を持つ、惑星が恒星の中に入らない、TRAPPIST-1 の 7 個の惑星の並び、トランジットの時刻に惑星が恒星と地球の間にいる、系外惑星のそばのワープホールの確かめ
- 画面（WebGL2）：TRAPPIST-1（恒星の近くと e の近く）、かに座 55 番星の d、シリウスのまわり（自動で作った惑星）。HUD に「TRAPPIST-1 eの表面から」と出る

## いまの制限

- **連星**：惑星を持つ最初の星を恒星にし、XML の系の座標で星のデータを探す。そのため、プロキシマ・ケンタウリの惑星は、ケンタウルス座α星 A（`H71456`）のまわりに付く（星のデータに HIP 番号が無く、名前で探せないため）
- 恒星系の間の宇宙では、いちばん近い恒星が切り替わったときに天体の一覧が入れ替わる。恒星系の外側の惑星（数十 AU）は、隣の恒星の方が近い場所では見えない
- 自動で作る星（`G…`）と HYG の星は、恒星の大きさを色と明るさから推定している
