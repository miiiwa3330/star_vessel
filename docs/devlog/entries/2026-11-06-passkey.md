# パスキー

回復コードの次に、オーナーと決めた順番でパスキーを足した（[回復コードの記録](2026-11-06-account-recovery.md)）。仕様は [`../../product/top-screen.md`](../../product/top-screen.md)、仕組みは [`../../tech/server.md`](../../tech/server.md)。

## 判断

- **`@better-auth/passkey` を使う**：WebAuthn の検証を自分で書くと、間違えたときに危ない。Better Auth の公式のパッケージで、版を本体（1.7.17）に合わせた（最新の 1.7.18 は本体の更新も要る）
- **パスワードと併用**：パスキーだけの登録は作っていない。パスワードをやめるかは、本物の端末で確かめてから決める
- **`residentKey: 'required'`**：既定の `preferred` だと、端末がアカウントを出せない鍵になることがある。ユーザー名を忘れても入れるのが目的なので必須にした
- **足すときにパスワードを求めない**：回復コードの作り直しとは揃っていない。プラグインに「パスワードを確かめてから」の仕組みが無く、Better Auth の「ログインから 1 日以内」の確認に任せた。揃えるなら、作り直しと同じ確認を挟む処理が要る

## 調べて分かったこと

前の話で「端末に仮のメールアドレスが出るかもしれない」と書いたが、ソースを読むと、端末に渡す名前は `user.name`（ユーザー名）だった。心配は要らなかった。仮想の認証器の鍵の中身でも確かめた。匿名の引き継ぎも、anonymous プラグインが `/passkey/verify-authentication` を見ているので、追加の処理は要らなかった。

ブラウザでパスキーの画面を閉じると、`NotAllowedError` が `ERROR_PASSTHROUGH_SEE_CAUSE_PROPERTY` という記号で返る。時間切れも同じ記号なので、「自分でやめた」として扱い、エラーを出さない。

## 確かめ方

Chrome の仮想の認証器（CDP の `WebAuthn.addVirtualAuthenticator`）で通した。やめる操作は、`navigator.credentials` を差し替えて `NotAllowedError` を起こした。ログインから時間がたった状態は、手元の D1 の session の時刻を書き換えて作った。

**本物の端末（Face ID・指紋・端末をまたぐ同期）は、まだ確かめていない。** HTTPS とドメインが要るので、本番かそれに近い環境で確かめる。

## 残っていること

- パスキーでは入れるが、パスワードも回復コードも無くした人は、回復コードを作り直せない
- パスワードをやめるか：[`requirements.md`](../../product/requirements.md) の「決まっていないこと」
- パスキーはドメインに結びつくので、本番のドメインを変えると使えなくなる。公開の前にドメインを決める
