# タイトル画面：スクロールと詳細・アイコン・出現の動き

オーナーから、タイトル画面の改善の続きを指示された。仕様は [`../../product/top-screen.md`](../../product/top-screen.md)、前の作り直しは [`2026-11-06-title-ui.md`](2026-11-06-title-ui.md)。

## 指示と、したこと

| 指示 | したこと |
|---|---|
| 仮の球体を出さない | 読み込み中の CSS の球体をやめた。3D を使わないとき・描けなかったときだけ出す |
| 描ける状態になってから、画面の下からフェードイン | 画像・描画の準備・シェーダーのコンパイルが終わってから現れ、地球が下から約 1.6 秒で上がる |
| スクロールで、地球の下半分が画面の上に来る視点まで（中間では止まらない） | 2 つの画面の間を、止まらずに動く。背景の地球が、動きに合わせてカメラで動く |
| その下に、サービスの詳細 | 文章を書いた（仮） |
| 右上に X と Miiiwa のアイコン | リンクつきで置いた |
| 画面全体のタップをやめ、START のまわりだけ | 約 330×110px |
| 一言を細字に | font-weight 200 |

アイコンのリンク先は、リポジトリにも docs にも手がかりがなかったので、オーナーに聞いた：X は `https://x.com/miiiwa3330`、Miiiwa は `miiiwa.com`。Miiiwa のアイコンの画像は、「`dev/miwa-portfolio` を参照して」とのこと。

## 参照した別のプロジェクト

AGENTS.md は「このリポジトリ以外は参照しない。`~/Desktop/dev/` 配下の他のプロジェクトは、star_vessel とは無関係」と決めている。今回はオーナーが明示的に参照を指示したので、**アイコンの画像を探す目的だけ**で、`~/Desktop/dev/miwa_portfolio`（指示は `miwa-portfolio` だったが、実際は下線）を読んだ。オーナーのロゴは、オレンジの 3 つの点と、黒い 3 本の縦棒（「iii」）。星の見た目や docs の根拠には使っていない。黒い棒は暗い背景で見えないので、明るい色にして、図形だけの SVG としてこのリポジトリに書いた。

## 決めた考え方

- **カメラは「距離」と「地球の中心の高さ」の 2 つだけを動かす**。最初の画面では、地球の上の縁が画面の下に見える（地球の中心が画面の下の外）。詳細の先頭では、地球の中心を画面の上の端のすぐ上に置き、地球の見かけの半径を画面の高さの 0.9 にする。すると、下半分が画面の上に入り、下の縁が上から約 4 割の高さに来る。スクロールの量（0〜1）を、なめらかな曲線（smoothstep）で、2 つの間に当てはめる。船を見せるカメラの位置（前回の `subjectView`）はそのまま使い、そこから距離と角度だけを変える。`subjectView` が、カメラの位置を決める 4 つの値（`basis`）も返すようにして、あとから作り直せるようにした
- **出現の動きは、角度を足すだけ**。地球の中心を画面の下へずらす角度を、最初は大きく、3D が描けてから 2.8 秒で 0 にする（先が緩やかな 3 次の曲線）。距離や向きは触らないので、地球は、本当に下から上がってくる
- **見せる準備を、見せる前に済ませる**：`compileAsync` で、シェーダーのコンパイルを先に済ませる。済ませないと、現れる最初の数フレームが引っかかり、「処理的に表示できる状態になってから」の動きがぎこちなくなる
- **詳細より先へスクロールしたら、地球の canvas を `translateY` で上へ送る**。スクロールの位置は、最初の画面の高さ（`.top-hero` の高さ）を 1 として、毎フレーム読む。画面の高さではなく最初の画面の高さにしたのは、横長のスマホで、最初の画面が画面より高くなっても合うように

## 確かめ中に見つけたこと

- **CSS の `scroll-snap` だけでは、ホイールを少し回すと、最初の画面へ戻る**。`mandatory` でも、ブラウザは「近い方」へ吸い付くので、ホイール 300px までは戻り、420px で詳細へ進んだ（Playwright で測った）。マウスのホイールをふつうに回す（1 目盛り 100px 前後）と、「スクロールしたのに動かない」ことになる。そこで、ホイールの向きに、1 回で隣の画面まで動かす処理を足した（`src/top/section-scroll.ts`）。動かしたあとの 0.7 秒は、ホイールを捨てる（トラックパッドの余韻で、詳細が勝手に動かないように）。詳細の中のスクロールは、ブラウザに任せる。指のスクロールとキーボードは、もとのままで足りたので、足していない
- **Space・PageDown でスクロールできない**：このページは `html, body` が `overflow: hidden` で、スクロールするのは `.top` という箱。キーボードのスクロールは、焦点のある箱が対象なので、焦点が無いと効かない。`.top` に `tabindex="-1"` を付けて焦点を置いた（Tab の順には入らない）。それに合わせ、「どこにも焦点が無いときの Enter で進む」の判定に、`.top` に焦点があるときを足した
- **前回、`Space` を、進む操作に奪っていた**。画面全体のタップをやめたので、Space は、スクロールに使うようにした
- **ほかの端末の細字**：日本語の細い書体は、端末のものを使う。Web フォントを足すと、日本語は 1 つの太さで数百 KB になるので、足していない。細い字が無い端末（Android など）では、ふつうの太さになる。公開の前に、実機で確かめる
