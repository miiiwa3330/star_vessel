# 土台作り：地球と星空を表示する

Vite ＋ TypeScript ＋ three.js（`three/webgpu`）で、現実のいまの時刻の地球・月・惑星と、HYG の約 12 万個の星を表示した。決まりは [`../../tech/world-model.md`](../../tech/world-model.md)。

## 確かめたこと

- **地球の向きが現実と合っている**：UTC 14:26 の画面で、地球の中央（太陽の真下の地点）がブラジルの東の沖（南緯約 15 度・西経約 33 度）になった。11 月 4 日の太陽の赤緯（約 −15 度）と均時差（約 +16 分）から計算した位置と一致する。テストでも、UTC 正午に経度 0 度付近、夏至に北緯 23.4 度を確かめている。自転の向きをわざと逆にすると、3 件が落ちた
- **WebGPU と WebGL2 の両方で動く**：Chrome（ヘッドレス）で、WebGPU のときと、WebGPU を消したとき（自動で WebGL2 に切り替わる）の両方を画面で確かめた。390×844（スマホの幅）でも確かめた
- 確かめ方：作業用フォルダに playwright-core を入れ、開発サーバーの画面を撮った（リポジトリには入れていない）

## つまずいたこと

- **WebGPU では点を 1 ピクセルでしか描けない**。`Points` で星を描くと大きさが効かない。three.js の `PointsNodeMaterial` の説明どおり、`Sprite` に `count` を入れて、板を星の数だけまとめて描くようにした
- **Codeberg の `/raw/` からは HYG の本体が取れない**。Git LFS で置かれているため、`/raw/` では 133 バイトの目印のファイルが返る。`/media/` から取る。`tools/build-stars.mjs` は、取れたものが gzip かどうかを確かめてから使う
- **TypeScript の型で `instancedBufferAttribute` の型が決まらない**。2 つ目の引数に `'vec3'`・`'float'` を渡して型を決める
- **星の明るさ**：最初の付け方では暗い星が一面に同じ明るさで散らばり、明るい星が目立たなかった。差を広げた（値と理由は `src/world/stars.ts` の `starAppearance`）

## 決めたこと

- **自分の位置は、基準の天体からの相対位置で持つ**。太陽中心のままだと、地球が秒速約 30 km で離れていく。影響圏（Laplace の式）で基準を選ぶ
- **恒星と太陽系は別の場面で描く**。単位（pc と km）が違うため
- **奥行きは対数の奥行き**。逆向きの奥行きは WebGL2 の古い端末で使えないことがある

## 残っていること

- 惑星が遠いと見えない（目印が要る）／星の明るさが地球から見た値のまま／ワープが無い／天体の中に入れてしまう
- 書き出した JavaScript が約 1.1MB（圧縮で約 320KB）。大半が three.js。読み込みの速さを測ってから、分け方を考える
