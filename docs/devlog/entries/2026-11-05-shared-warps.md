# ワープホールを全員で共有する

## 決まったこと（オーナー、2026-11-05）

- 同時接続は数百人を目安、アカウントは登録なしで始めて後から登録、1 人 3 個まで
- サーバーは Cloudflare にまとめる（比べた候補は [`../../tech/stack.md`](../../tech/stack.md)）
- **ワープホールの名前は「宇宙の住所」**。最初にオーナーが「NX-T-001 のような感じ」と言い、意味の解釈を確かめたところ、例は仮のもので「日本、東京、大田区、西六郷、2-45-4 のように、大きなカテゴリーから狭めて一意に指すコード」にしたい、となった。銀河 › 腕 › 恒星系 › 惑星 › 衛星 › 番号 の 6 階層を提案し、決まった（[`../../tech/world-model.md`](../../tech/world-model.md) の「宇宙の住所」）

## 作り方で考えたこと

- **番号はサーバーが振る**。全員で重ならないようにするため。住所ごとの最後の番号を別のテーブルに持ち、消した番号は使い回さない
- **上限（3 個）と番号を同時に守る**：D1 は途中で判断を挟むトランザクションが使えない（`batch` だけ）。「上限を超えていなければ」という条件を、番号を進める文と置く文の両方に入れて、1 つの `batch` で動かした。同時に 6 回送って、3 回だけ通り、番号が欠けないことを確かめた
- **Better Auth のテーブルを手で書かない**：Better Auth のマイグレーションの機能を、Node.js 組み込みの SQLite（`node:sqlite`）に向けて動かし、SQL を作らせた（`tools/gen-auth-schema.ts`）
- **一覧を一定の間隔で取り直さない**：人数が増えると Workers の無料の上限をすぐ使い切る。一覧を開いたときに取り直す

## つまずいたこと

- **開発サーバーが 504（Outdated Optimize Dep）を返し続けた**。起動したまま新しいパッケージ（better-auth）を入れたため、Vite の下準備の情報が古くなった。オーナーが動かしていた開発サーバーだったので止めず、確認は別のポート（5174）・別の下準備の置き場所で起動したサーバーで行った。直すには、開発サーバーを起動し直す
- npm 11 がインストール時のスクリプト（esbuild・workerd など）を止めた。許可しなくても動くことを確かめ、許可はしていない

## 確かめたこと

- API（curl）：匿名のログイン、置く、4 個目は 409、番号が住所ごとに続く、ほかの人のものは消せない、消した番号は使い回さない、ログインなしは 401、正しくない置き場所は 400
- 画面（Chrome、1280×800 と 390×844）：起動 → 匿名のログイン → 置く（`MW-ORI-SOL-3-0-005`）→ 一覧。スマホの側（別のアカウント）の一覧に、PC の側が置いたものが出る
- テスト 46 件、型チェック（ブラウザ側と Worker 側）

## 残っていること

- 本番に出していない（[`../../tech/server.md`](../../tech/server.md) の「本番に出す前に残っていること」）
- 後から登録する画面と、そのときのワープホールの引き継ぎ
- 置く場所はブラウザの言うことを信じている
