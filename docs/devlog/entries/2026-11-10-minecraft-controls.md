# マインクラフトの操作感を真似た操縦

オーナーの指示で、世界（`/play`）の操縦をマインクラフト（クリエイティブの飛行）の操作感に合わせた（要件 F60）。

## 決めたこと（オーナーへの確認）

1. **PC はカーソルを出さず、Esc でポーズ画面（ゲームメニュー）に移動してカーソルを出す**（Pointer Lock）
2. **上下の制限はかけず、傾き（Q/E）も残す**。W/A/S/D と Space/Shift の割り当てをマイクラに合わせる
3. **W/A/S/D はいま見ている視点の向きにそのまま進み、Space/Shift の上下もいま見ている視点の上下を上下とする**
4. **ダッシュ（W の 2 回押し・Ctrl）・慣性・F5 の 3 視点（一人称 → 後ろから → 前から）・スマホの十字と上昇／下降**も真似る

## 試してやめた案：向きを「船」と「頭」に分けて水平面で進む

最初はマイクラのクリエイティブ飛行と同じく、向きを「船の向き（`body`）」と「頭の上下の角度（`pitch`、±90° まで）」に分け、上や下を見ても W/A/S/D は船の水平面で進む形を作った。しかし宇宙では地面が無いため、見ている方向にそのまま進めない・視点の上下と Space/Shift の上下がずれる感触になり、オーナーの指示で元の「いま見ている視点の向き（`orientation`）の前後・左右・上下にそのまま動く」形に戻した。

## 慣性とダッシュの値

マインクラフト Java 版のクリエイティブの飛行は、1 tick（0.05 秒）ごとに水平の速度に `0.91`、上下の速度に `0.6` を掛ける。フレームの速さに左右されないよう、連続の指数減衰 $e^{-\Delta t / \tau}$ に直した（`src/controls/movement.ts`）：

- 前後・左右の時定数 $\tau_h = 0.05 / -\ln(0.91) \approx 0.53$ 秒
- 上下の時定数 $\tau_v = 0.05 / -\ln(0.6) \approx 0.10$ 秒（視点の上下方向の成分はすっと止まる）
- ダッシュは 2 倍、W の 2 回押しは 7 tick（0.35 秒）以内。一度始まると、前へ進むのをやめるまで続く（Ctrl を離しても続く）

宇宙には空気の抵抗は無いので、これらは遊びの感触のための演出。

## Pointer Lock とゲームメニュー

- ブラウザの `requestPointerLock` は、ページを開いた瞬間には呼べず、ユーザーのクリックの中でしか通らない。そのため PC では最初にゲームメニュー（「ゲームに戻る」「タイトルへ」）を出し、「ゲームに戻る」か画面のクリックでカーソルを消して操縦に入る。初めての宇宙船選びが出ているときは、その「この船にする」「あとで」のクリックの中でそのままカーソルを消すので、2 回押さなくてよい
- ほかのプレイヤーがいる宇宙なので、ゲームメニューの間も世界の時間と描画は止めない。後ろを少し暗くするだけでクリックは通すため、ワープ・スタンプなどの画面のボタンは Esc でカーソルを出している間にそのまま押せる
- Shift を下降にしたので、ホイールの「1 段で 10 倍」は Ctrl＋ホイールにした（Mac では Shift＋ホイールが横スクロールに化けるので、`deltaX` も見るようにして Shift も残した）

## 確かめたこと

- `npm test`・`npm run check`・`npm run build`
- Chrome（WebGPU と、WebGPU を消した WebGL2 の両方）とスマホ幅（390×844、タッチ）で `/play` を開き、ゲームメニュー → クリックで Pointer Lock → 視点を上に向けて W でその向きに進み、Space/Shift で視点の上下に動くこと・W の 2 回押しと慣性・F5 で「後ろから」「前から」の切り替え・Esc でゲームメニュー、スマホで十字と上昇・下降のボタンが重ならずに出ることを画面で確かめた
