# タイトル画面のスクロールが詳細の先頭で止まる・カクつくのを直す

[`2026-11-06-title-inertia.md`](2026-11-06-title-inertia.md) の続き。仕様は [`../../product/top-screen.md`](../../product/top-screen.md)。

## 指摘

- 一定以上の速さで下へスクロールすると、止まる感じがする。最初の画面から詳細へ来た瞬間に回すと、しばらく動かず、そのあとカクつきながら下へ進む
- スクロールを少し遅くして、一定以上の速さが出ないようにしてほしい

## 原因

直す前に、ホイールの列を流してフレームごとの位置を記録し、再現した。詳細の先頭（720px）で **300〜615 ms 止まり**、そのあと **1 フレームで最大 120px 飛び、瞬間の速さは最大 7229px/s** だった。

1. **止まる**：前の作りは、2 つの画面の間を動く間と、止まったあとの 0.25 秒、ホイールをすべて捨てていた（トラックパッドの余韻で詳細が勝手に動かないように）。ばねは最後がゆっくりなので、捨てている時間が長く、続けて回す人には「動かない」になる
2. **カクつく**：捨て終わると、ブラウザのスクロールに切り替わる。ここで動きの速さが 0 から急に変わる。ブラウザのスクロールには速さの上限も無い。さらに、地球（canvas）はメインスレッドで動かし、ブラウザのスクロールは別のスレッドで動くので、2 つがずれる余地もあった

どちらも「2 つの動きを境目で切り替える」ことから来ている。

## 直し方

**タイトル画面のホイールは、詳細の中も含めて、全部自前の 1 つの動きにした**。行き先を 1 つ持ち、位置はそこへ近づくだけなので、境目で動きが切り替わらない。

- 詳細の中だけブラウザに任せたままにする案は、やめた。境目の切り替えが残るうえ、速さの上限を付けられない（ブラウザのスクロールの速さは、ホイールの列を間引くことでしか抑えられず、それ自体がカクつきになる）
- 指（スマホ）とキーボードは、これまでどおりブラウザと CSS の吸い付きに任せる。指の慣性はブラウザの方がよく、ホイールの問題でもないため

### 速さの上限

- **上限 1200px/s**。前の動きの山は 1800〜2600px/s で、「少し遅く」の目安で約半分にした。720px を約 1.5 秒で動く。**見た目のための値で、触って調整する前提**
- **回転量は 0.8 倍**。詳細の中の読むスクロールも少し遅くするため
- 上限だけだと、強く回した分が貯まって、手を止めたあとも長く流れる。そこで**行き先を今の位置から `2 × 上限 ÷ ω`（300px）より先に置かない**。この長さは、上限の速さで動いているときのばねの遅れと同じで、短いと上限に届かず、長いと流れ続ける
- ばねの強さを 6.5 → 8 rad/s にした。追従の遅れ（2/ω）が 0.31 → 0.25 秒になる。詳細の中を読むトラックパッドの操作で、遅れが長いと重く感じるため。上限があるので、強くしても速くはならない
- 上限を入れると、ばねの加速が大きいので、2〜3 フレームで上限に届いて急な動き出しになる。**加速にも上限（7000px/s²）を付けた**（減速は、ばねのまま。だから、行き過ぎない保証は崩れない）

### 余韻と、新しい操作の見分け

オーナーの指摘は「着いた瞬間に回しても動かない」だが、ただ捨てるのをやめると、軽いフリックの余韻で、詳細が勝手に流れる（前の devlog で捨てていた理由）。両立させるため、**同じ操作の続きか、新しい操作か**を見分ける。

- 同じ操作の続きは、詳細の先頭で 500px 分だけ受け止める。超えるほど強く回し続けたら、通り過ぎる（＝一定以上の速さでは、止まらない）
- 新しい操作は、受け止めない
- 新しい操作とみなすのは、**間が 120 ms 以上空いた・向きが変わった・山から十分減った回転量がまた増えた**のどれか。増えただけで新しい操作にしないのは、1 回のフリックの立ち上がりも増えるから。間だけにしないのは、余韻の途中でもう一度回すと、間が空かないことがあるから

## 確かめ中に見つけたこと

- **測り方の誤り**：Playwright の `mouse.wheel` を 1 回ずつ `await` すると、列の再生が数倍遅れ、「2 回目のフリックの前に 1100 ms 止まった」と出た。コードではなく、1 回目のフリックがまだ再生中だった。待たずに送る形に直して、着いた瞬間に当てて測った。着いた瞬間に回して 3px 動くまで約 100 ms、30px 動くまで約 180 ms
- **描画の重さは原因ではなかった**：直す前の測定でも、フレームの間隔の中央値は 16.7 ms で、フレームは落ちていなかった。直したあとは、WebGPU と WebGL2 のどちらでも同じ数字になった
- **直す前の「飛び」は大きめに出ている可能性がある**：自動で送るホイールには、ブラウザの滑らかなスクロールが効かないことがあり、1 フレームで 120px・7229px/s は、実物より大きいかもしれない。詳細の先頭で止まる時間（300〜615 ms）は、ホイールを捨てる作りから来ているので、実物でも起きる

## 残っていること

- **実物のトラックパッド・マウスでは確かめていない**（自動の確かめは、それらしいホイールの列を流したもの）。余韻の出方は端末で違うので、受け止める量（500px）と見分けの間（120 ms）は、触って調整する余地がある
- 指のスクロール（スマホ）には、速さの上限が付いていない
