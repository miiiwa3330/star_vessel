# 天体を増やす（惑星の模様・衛星・系外惑星）

## 決まったこと（オーナー、2026-11-05）

着手前に論点を洗い出し、3 回に分けて決めた（要件 F19〜F24）。

| 論点 | 決定 |
|------|------|
| 進め方 | `feature/more-bodies` で、タスクごとにコミットして push（PR は作らない） |
| 惑星の画像 | 配布元（Solar System Scope）に開発の環境から接続できないため、画像はオーナーが後で置く。それまでは模様を自動で描く |
| 衛星の範囲・番号 | データが手に入る衛星はすべて。番号は天文学の正式な番号 |
| 小惑星の範囲・番号 | データが手に入るものはすべて。住所は A＋小惑星番号 |
| 系外惑星 | 実在＋自動生成、観測の割合、恒星に近い順の番号、種類ごとの模様、公転させる、作り方に世代番号 |

## 天体の一覧と id を作り直した

- これまでは 11 個の天体を型（`BodyId` の文字列の和）で固定していた。衛星・系外惑星を足すため、**一覧（registry）に登録する形**にした。描画・衝突・基準の天体・レーダーは一覧を見るだけにした
- **id に住所の番号を含めた**（`S5.1`＝イオ、`A1`＝ケレス、`H70666.2`＝系外惑星）。サーバーはワープホールの住所を付けるとき、天体の一覧を持たずに id の形だけで番号を決めて確かめられる。サーバーに天体のデータ（数百 KB）を持たせずに済む
- 既存の id（`Earth`・`Moon` など）は変えていない。保存済みのワープホールはそのまま使える

## データ元に接続できなかった

開発の環境（クラウドのコンテナ）のネットワークの設定で、JPL（衛星の軌道・小惑星）・Minor Planet Center・Solar System Scope・Codeberg に接続できなかった。GitHub と npm にはつながった。

- 衛星はガリレオ衛星の 4 つだけ足した。位置は astronomy-engine の `JupiterMoons`、半径も astronomy-engine の定数で、外のデータが要らないため
- 残りの衛星と小惑星は、データの出どころが確かめられないので、まだ足していない（GitHub にある写しは出どころやライセンスが分からないものが多く、AGENTS.md の「出どころの分からない素材は置かない」に当たる）
- 系外惑星のデータ（Open Exoplanet Catalogue）は GitHub が配布元なので取得できた

## 系外惑星の恒星の見つけ方

- 星のデータ（`stars.bin`）には名前（HIP 番号など）が無いので、方向と距離で同じ恒星を探した。方向 0.03 度以内・距離の比 0.6〜1.6 倍。769 の系が HYG の星と一致した
- 一致しない 2,935 の系（暗くて HYG に無い星）は、新しい恒星（`E`＋名前のハッシュ）として足した
- 連星は、XML の系の座標で探すので、プロキシマ・ケンタウリの惑星がケンタウルス座α星 A に付いてしまう。恒星が自分の座標を持っていればそれを使うようにしたが、プロキシマは持っていなかった（いまの制限）

## 自動で作る惑星

- 数（惑星があるか・いくつか・木星型か）は、乱数との大小の比べだけで決めた。対数・指数を使うと、ブラウザによって最後の桁が違い、境目で数が変わるおそれがあるため（AGENTS.md）
- 割合は観測の論文の結果を丸めた値（[`../../tech/exoplanets.md`](../../tech/exoplanets.md)）。太陽に似た恒星 2,000 個で、惑星を持つ割合が 0.7〜0.8 に入ることをテストで確かめた
- 惑星の画像を作る時間を減らすため、系外惑星の模様は 256×128 にした（恒星系に入るたびに作るため）

## 試してやめたこと

- 縞の星の模様を sin の波で描いた版：木星が同じ幅の縞の並びに見えた。1 次元のノイズに変えた
- 縞を乱す強さ 0.35：木星の縞が渦に見えた。0.1 にした

## 確かめたこと

- テスト 100 件（型チェックも通る）
- 画面（WebGL2・swiftshader）：木星・土星（環）・火星・金星・海王星・イオ・TRAPPIST-1（恒星と e）・かに座 55 番星 d・シリウスのまわり。WebGPU とスマホの実機では、まだ見ていない
