# 図鑑：すべての天体・黒いシルエット・回せる絵・滑る詳細（2026-11-13）

オーナーの指示：情報のある天体をすべてコレクションに入れる。訪れていない所は黒いシルエット。詳細の天体はくるくる回せる。一覧から詳細へは、画面を切り替えず天体が滑る。詳細の情報をもっと多く（教養を得るサービスでもある。スクロールするほど多くてよい）。一覧に「全体の数分の取得数」を出す。

作業の前に、オーナーに 4 つ聞いた（作業中は質問を受け付けないため）。答え：範囲は名前のある実在の天体、訪れていない天体は名前を「？？？」・詳細は種類だけ、説明はデータ＋主な天体は AI が書く、番号は全部を通しの 1 本。

## 入れる範囲

- データにある天体は、恒星（HYG）約 12 万・小惑星 約 90 万などを合わせると 100 万をこえる。全部入れると、ほとんどが番号だけの星の黒いシルエットになり、何万ページも続く。「名前のある実在の天体」に絞ると 26,216 個になった
- 恒星は、HYG の固有名（proper）のある 540 個と、系外惑星のある恒星。HYG の固有名は、星のデータ（`stars.bin`）に入れていなかったので、名前・符号・スペクトル型・見かけの等級・星座だけの小さな表（`star-info.json`。54 KB）を別に作った。`stars.bin` の形を変えると、`stars.bin` を読むほかのツールも直すことになるため
- 彗星は、データの 4,048 個のうち、番号の付いた周期彗星と人の名前の付いた彗星にした。観測計画の名前（NEOWISE・ATLAS など）の彗星は、同じ名前が何十個も並ぶだけなので外した（それでも 1,491 個）
- 白色矮星（16,676 個）は、名前がカタログの番号（WDJ…）だけなので外した。パルサーも名前は J 名だけだが、オーナーに示した選択肢に入れていたので入れた
- 図鑑に入らない天体（自動で作った星など）を訪れたら「番外」として最後に出す。前の図鑑は訪れた天体を全部見せていたので、見えなくならないように

## 番号

- 通しの 1 本の番号を、どの順に振るか。太陽系を先に決まった順（太陽・惑星とその衛星…）で並べ、そのあとを太陽から近い順にした。「近いものほど若い番号」なので、遠くへ行くほど番号が大きくなり、旅の進み具合と番号が合う
- 恒星のすぐ後ろにその惑星を並べたので、恒星系ごとにまとまる

## 回せる絵を canvas に 1 画素ずつ描く

- three.js の 2 つ目の描画（WebGPU）を作る案も考えた。図鑑を開くたびに作ると重く、宇宙の描画と GPU を取り合う。天体 1 つなら、2D の canvas に 1 画素ずつ（球の 1 点ずつを地図の経度・緯度にして色を取る）描いても 1 回 数 ms で足りた。環やブラックホールの円盤は、視線と赤道の面の交わりで同じ処理の中に描ける
- 球のふちに細い暗い線が出た。大気のにじみ（球の外）と、球のふち（なめらかにするために薄くしていた）の間に、どちらも薄い画素の筋ができて、後ろが透けていた。大気のある天体は、ふちの色を大気の色へつなぐようにした
- 星雲は、薄い光の点を何百枚も足し合わせるので、8 ビットの色の段差が格子の模様に見えた。点の明るさを下げ、canvas を少しだけぼかした
- 球状星団は、プラマーの分布で外へはみ出した星を半径 1 で止めていたので、ふちに輪ができた。はみ出したものは選び直すようにした

## 滑る動き

- 一覧と詳細を同じ場所に重ね、詳細を出すときに、押した絵の位置と大きさ（一覧）から、詳細の絵の位置へ、Web Animations の transform で動かした（FLIP）。一覧は消さずに薄くするだけなので、戻るときもその場所が測れる。詳細で前・次の天体へ移ったあとに戻ると、その天体が別のページにあることがあるので、先にそのページへ移ってから測る
- スクリーンショットは撮るのに時間がかかり、途中の動きが写らなかった。位置を 80 ms ごとに測って確かめた（幅 76 px → 110 → 268 → 312 → 340）

## 解説の文

- 解説は、太陽・惑星・主な衛星・探査機 18 機すべて・明るい恒星・名前のある星雲や銀河など、約 140 の天体に書いた。どの天体にも種類の説明（恒星とは、など）を続けるので、解説の無い天体でも読むものがある
- 数値は、文には確かなものだけを入れ、くわしい数は表に任せた。太陽・惑星の数は、NASA の Planetary Fact Sheet を取得して、表の値をそのまま写した（文の中の数と表の数が食い違わないように）
- 書いたあと、自信の持てなかった所を読み返して 4 か所直した（フォボスの大きさ、エンケ彗星の周期の書き方、池谷・張彗星の年、系外惑星の数）。人の目での確認はまだ

## 追記（同じ日）：マイページの下にも図鑑

- オーナーの指示で、タイトル画面のマイページ（火星の箱）の下へスクロールすると、同じ図鑑が出るようにした
- タイトル画面は世界のデータを読まない（軽く開くため）。図鑑には星・系外惑星・星団などのデータ（約 9 MB）が要るので、**図鑑が画面に入ったときに初めて読む**ようにした。three.js は要らないので、図鑑に要るデータだけを読む入口（`collection-loader.ts`）を別に作った。世界の画面は、宇宙を描くために同じデータをすでに読んでいるので、そちらは main.ts の読み込みのまま（読むデータを足すときは両方を直す）
- 図鑑の幅が 263 px ほどに縮んだ。箱はもともと、中身を真ん中にそろえる `justify-items: center` の grid で、マイページでは block に変えていたが、Chrome は block の並びにも `justify-items` を当てるので、図鑑が中身の幅まで縮んでいた。マイページでは `stretch` にした
- 確かめたこと：匿名で月・火星・木星を訪れてから、タイトル画面でサインアップ → 宇宙船名を押して火星へ → 「COLLECTION ↓」→ 図鑑が「5 / 26,216」（匿名の記録が引き継がれている）→ 火星の詳細（ボタンは「一覧へ戻る」だけ）→ Esc で地球へ戻る。PC 1440×900 とスマホ 390×844。確かめるため、手元の D1 にテストのアカウント（probe_…）を 5 つ作った

## 追記（同じ日）：マイページもタイトル画面と同じスクロールに

- オーナーの指示：トップページと同じように、背景の星（火星）を動かして、下の画面にコレクションを出す。マイページでも右下のポートフォリオと X を押せるようにする
- 背景の天体の動きは、スクロールの位置（最初の画面の高さを 1）を 3D の描画に渡す形（タイトル画面と同じ `getScroll`）。月・火星に着いているあいだは、これまでスクロールを使っていなかったので、行き先のカメラにも、タイトル画面の地球と同じ「詳細の画面のときの距離と高さ」へ動く式を入れた
- そのままだと、図鑑の画面から閉じると、地球へ戻る飛行の始まりで、火星が最初の構図へ跳んだ（閉じた瞬間にスクロールの位置が 0 になるため）。着いているあいだの最後の位置を覚えておき、戻る飛行はそこから始めるようにした
- ホイールはタイトル画面と同じ部品（`attachSectionWheel`）を、マイページの面に付けた。ただ、それだけだと図鑑の詳細の説明（中でスクロールする）がホイールで動かなくなった（ホイールをすべて受け止めるため）。図鑑の画面にいる間は、中のスクロールできる所が動けるならそちらへ渡し、上へ動けないときだけ、上の画面へ戻すようにした
- 右下のアイコンは、マイページの面（下の画面を動かすため、面全体で押せるようにしていた）の下になっていたので、手前に出した
- 確かめたこと：PC でホイール 1 回で 0 → 900 px（図鑑の画面）、地球の詳細の説明がホイールで 400 px 動き、面は動かない。一覧で上へ回すと 0 に戻る。右下のアイコンは、どちらの画面でも、その位置の一番手前がリンク（elementFromPoint）。スマホでも COLLECTION ↓ で図鑑の画面へ移り、火星が上にかかる

## 追記（同じ日）：図鑑の画面をタイトル画面の詳細と同じ配置に

- オーナーが、タイトル画面の詳細（地球が上にかかり、その下に ABOUT）の画面を見せて「この配置のバランスに」と指示した。それまでは、図鑑の面を画面の真ん中に置いていたので、火星が面の後ろに透けていた
- 詳細の画面と同じ数（上の余白 `clamp(230px, 46vh, 480px)`・幅 880px まで）を使った。図鑑は 1 画面に収まらなくなるので、下へスクロールして見る（タイトル画面の詳細と同じく、火星はページと一緒に上へ送る）。そのため、図鑑の画面の中のホイールは、図鑑の下の端に来るまでは、マイページの面を動かすようにした
- スマホで、プログラムで一番下へ動かすと、吸い付きで図鑑の先頭に戻った。指のスクロール（CDP の synthesizeScrollGesture）では、図鑑の中を自由に動けた（タイトル画面の詳細と同じ動き）
